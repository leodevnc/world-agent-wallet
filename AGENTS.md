# Project language

- Use English for first-party UI, accessibility labels, documentation, error messages, CLI output and default examples.
- Preserve user-provided names, input data and multilingual test fixtures in their original language.
- Keep API identifiers, payment states, authorization rules and budget time-zone semantics unchanged when editing presentation text.
- Validate text changes with the existing tests and the local demo. Do not use real World accounts, wallets or funds for language or UI checks.
